04 · Why

필요성과 어려움 — 현지화 시행착오

핵심 메시지

같은 제품도 시장과 사용자가 달라지면 다른 맥락에서 사용됩니다. Second Context는 그 맥락을 이해하고 제품 경험에 반영합니다.

왜 어려운가

현지화는 번역만으로 끝나지 않습니다. 사용자가 일하는 방식, 제품을 이해하는 방식, 신뢰를 판단하는 기준이 함께 달라집니다. 한국 시장에 맞춰 제품을 만들어 온 팀은 이 차이를 내부에서 발견하기 어렵습니다.

시행착오 유형 (설명용 예시 — 실제 기업 사례 아님)

유형흔히 일어나는 일관련 질문
번역 중심 현지화화면 문구는 영어로 바꿨지만 온보딩이 국내 사용자를 전제로 설계되어 첫 사용자가 가치를 이해하지 못한다처음 방문한 사용자가 제품의 가치를 이해하고 시작할 수 있는가?
업무 방식 차이핵심 워크플로가 현지 팀의 역할 분담과 승인 방식에 맞지 않아 실제 업무에 쓰이지 않는다핵심 업무 흐름이 목표 사용자의 실제 업무 방식에 맞는가?
구조와 문구메뉴 구조와 버튼 문구가 다음 행동을 분명하게 안내하지 못한다화면의 구조와 문구가 다음 행동을 명확하게 안내하는가?
우선순위 부재고칠 것이 많아 보이지만 출시 전에 무엇부터 할지 정하지 못한다출시 전에 어떤 UX 문제부터 개선해야 하는가?

현재 홈(2026-11-11)에는 이 네 유형 표가 없습니다. Why Us는 문제의식 한 문단 + 차별점 3개로 바뀌었고(커밋 ce9b463, 2026-11-10), 이 표는 기획 근거로만 남깁니다. 실제 기업의 공개 사례는 출처를 확인한 뒤 추가합니다 — 추후 개선.

11 · Scenarios

사용자 시나리오

현재 구현으로 가능한 경로입니다. Calendly 페이지가 열린 것과 예약을 완료한 것은 다른 상태이며, 사이트는 예약 완료를 알 수 없습니다.

1. 미국 진출을 준비하는 파운더 (P1) → 상담 예약

방문 목적
미국 출시 전에 제품 경험을 점검받을 수 있는지, 누구와 어떻게 진행하는지 확인
  1. 홈 Hero의 영상과 제목에서 사이트가 다루는 문제(새로운 시장의 맥락)를 읽는다
  2. Why Us의 문제의식과 차별점 3개를 읽는다
  3. 같은 영역의 About Second Context에서 경력 수치(40+ · 12+ · 27+)와 경험 행 3개를 본다
  4. Services의 4가지 도움 중 필요한 것을 찾는다
  5. Work의 사례 카드를 눌러 사례 페이지(S-03)에서 설계 판단과 데모를 본다
  6. 홈 Approach 4단계를 보고, 필요하면 "진행 방식 자세히 보기"로 6단계를 확인한다
  7. 헤더의 "Book a 30-minute consultation" 또는 #contact의 "30분 상담 예약하기"를 누른다 → Calendly 새 탭. (Approach 상세에서 누르면 Contact 페이지 #booking을 한 번 거침)
  8. Calendly에서 시간을 고르고 예약을 확정한다 외부

완료 상태 사이트 기준 = Calendly 예약 페이지가 열림. 실제 완료 = Calendly 예약 확정 (확인 필요 — 별도 확인 항목)

2. 구체적인 개선 과제가 있는 프로덕트 리드·PM (P2) → 프로젝트 문의

방문 목적
특정 업무 흐름 개선을 외부와 함께할 수 있는지, 범위와 협업 방식을 내부에 설명할 근거 확보
  1. 홈 Services와 Work에서 비슷한 업무 제품 경험을 확인한다
  2. 사례 페이지에서 문제·역할·설계 판단·결과와 단계형 데모(사례 02는 탭 두 개)를 본다
  3. Approach 상세에서 단계별 산출물·기대 효과와 우선순위 매트릭스를 검토한다
  4. Hero·Approach 상세의 "프로젝트 문의하기" 또는 푸터 "Send a project inquiry"로 홈 #contact에 가서 이름·이메일·회사 또는 제품명·제품 URL·문의 내용을 적는다
  5. "문의 보내기" → 보내는 중… → 성공 안내·입력 초기화 (실패 시 입력 유지·재시도)
  6. 운영자가 메일함에서 문의를 받고 회신한다 운영

완료 상태 사이트 기준 = 서버 2xx 뒤 성공 안내. 실제 완료 = 운영자 메일함 도착과 회신 (확인 필요 — 별도 확인 항목)

3. 영어 콘텐츠를 선호하는 방문자 (언어 이용 경로)

방문 목적
같은 내용을 영어로 읽고 위 1·2와 같은 판단을 함
  1. 헤더(또는 푸터 맨 아래)의 "EN"을 누르면 같은 페이지의 영어판으로 이동한다
  2. 선택이 이 브라우저에 기억되어(localStorage sc-lang), 다음에 한국어 주소로 와도 영어판으로 열린다 — 2026-11-11 브라우저 확인
  3. 영어 페이지의 내부 링크는 영어 페이지로만 연결된다
  4. 상담 예약(Calendly) 또는 영어 문의 폼으로 문의한다(숨김 항목 language로 페이지 언어를 함께 보냄)
  5. 브라우저 언어·접속 국가에 따른 자동 이동은 하지 않는다(의도된 동작)

완료 상태 시나리오 1·2와 같음
